# Ash 应用：现在、成长与彼此的理解

涉及 MOBILE-ARCH §1.1–1.4、§2.1–2.6、§3.1–3.6、§4.1–4.3、§5、§6.1–6.5、§7.2、§11.1–11.2、§13.1。

## 第一期已实现

`ai.ash.sysapps.ash.AshActivity` 继承公共 `SystemAppActivity`。标题、列表与编辑器常驻；业务只经公共端口调词。动态内容使用 `KeyedRowsAdapter`，key 为任务、日期、记忆文件、成长记录或批注的真实 id。刷新保留原快照，单来源读请求合并，离页使旧回调失效。按 key/offset 保阅读位置；独立编辑器不会被后台刷新拆掉，文本实时存入应用自己的草稿偏好，重建恢复路由与编辑目标；应用复用时 onNewIntent 使用同一参数解析，保留旧草稿后切到新路由，旧编辑回执不会污染新编辑器。用户返回退出编辑会保留草稿。

首屏依次是：我现在在做什么、我手上的具体待办、最近收尾的事、我是谁 / 我记得你 / 日记 / 成长 / 我们的约定 / 你的批注。没有读取成功时不声称空闲或没有任务。具体待办与最近结果都来自 `service:tasks/list {subject:ash,status:all}`，界面按 todo/doing/waiting 与 done/dropped 分组。存在 next_before 时明确这里只显示最近更新的记录，并提供任务应用完整视图入口，不把局部分页说成没有待办。负责人和关注主体分开，Ash 不复制待办存储。打开任务应用传 `arg={subject:ash}`，完成也调用同一个 `done`。

- 现在：`service:history/current`、`service:pulse/pulse.get`，展示已经公开的工作与下一次主动整理时间，不编造内心活动。
- 人格：现有 `persona/get`、`propose`，补 `versions`，展示最近一次由谁、为何修改。人格仍由原关卡审批，界面不绕开确认。
- 记忆：`persona/memory.get/set` 读写 USER.md、MEMORY.md、PROACTIVE.md。允许编辑全文、删除错记内容，后写生效，无修订号或并发协议。全文没读全时拒绝编辑，避免用截断内容覆盖文件。
- 日记：复用 `memory/YYYY-MM-DD.md`，`diary.list/get/set`，按日翻页、批注。daily-review 通过词写日记和长期记忆，发出 `persona.changed`；原有直接写工作区的结果也在相应写入账本变化后重读。
- 成长：`growth.list/put` 保存已经发生的学习与改进：为什么开始、做了什么、效果、下一步、出处。它是成果记录，进行中工作仍在任务服务，主线不在这里另建。记录和批注使用稳定 id，重试不重复记一条。
- 约定：现有 `admin/settings.get/set`（免打扰）、`gate/rules.list/revoke`、`gate/mode.set`、记忆里的 PROACTIVE.md。规则撤销先说清影响再确认。改变审批/设置后按账本刷新。
- 批注：`persona/note` 按对象保存并在后台唤醒主 agent；她通过 `note.reply` 回应做了什么或为何没改。直接更正记忆/人格也补一条通知。通知失败如实保留提示，不把保存失败说成成功。未知写入结果保留草稿并要求查看现状，不自动重放。

外壳里的 HomeDocs（人格/记忆）和 HomePromises 已删除，主页对应三个旧块移除。旧深链接兼容转进 Ash 应用的对应 section，不再创建旧子页。

## 第二期设计，不写自动提炼代码

主线和待办只建一份，均归任务服务；Ash 应用读 `subject:ash` 的视角。主线是“学会替你管日程”“少打扰你”这类长期方向，采用任务服务将来的统一 thread 接口，绝不从成长日志派生另一套主线数据库。

每条主线用第一人称写：为何开始（主人哪次反馈/具体需要及出处）、已经做了什么（白话概括技能、应用和做法）、效果怎样（有依据，未知就说还在观察）、下一步（关联真实待办 id）。代码和规则只在凭据里展开，首屏不以代码清单解释成长。

待第一期待办验收通过，再和任务应用一起实现：从对话、反馈、技能/应用变化提出主线建议，附出处；主人可确认、纠正、合并、否掉，否掉后不重复提。活跃主线在前，冷下去的下沉，结束的归档。首屏仍先展示现在和具体待办，再展示这些主线，不用长期叙述掩盖未兑现承诺。

## 验证与边界

已运行的命令和结果以交付报告为准：服务侧 persona 测试，SDK 相关单测和生成物检查，TypeScript 编译；Android compileDebugKotlin 与 AshModelTest。Model 覆盖共享主体过滤、状态排序、旧响应/失败不清空、记忆编辑、日记解析与分页去重、已结束进度不伪装进行中。

没有操作手机。真实 IME/拼音 composing、旋转/分屏/进程回收、大字体/RTL/TalkBack、预测返回、断网重连及人/agent 同时操作的端到端场景仍未实机验证。系统注册表/Manifest 由底座 worker 统一登记；任务服务由 tasks worker 提供，集成需同时带上两项提交。

## 产品验收整改（10-16）

日常路径一：我对你的了解 → 具体的「会议周二」→ 修改为周三 / 删除 / 留纠正 → 保存前 memory.get 读取完整最新文档 → 只替换该事实 → memory.set → 同一 persona/note 通知主 agent。新添的其他记忆保留，目标已变或重复时不猜着改；全文退到高级入口。页面和首页展示「你纠正的那件事」及原批注关联的回应，不要求用户去读 Markdown。

普通批注路径会区分：保存且已通知、保存但尚未通知、送达结果未知。后两者可点同一条记录重试；persona 只记一个批注 id，已成功唤醒的 id 不再重复唤醒。没有后台队列或新的修订协议。

日常路径二：首页「我答应你的事」→ 某件承诺 → 待做 / 正在推进 / 卡在这里 / 事情的结果。原因读 note，结果读 result；没有写就直说未记录，不能把 todo 说成 doing。任务应用仍是同一份 subject:ash 数据，详情可按 id 打开它调整安排、看出处，返回后重新读取。文件和证据不占主路径。

「现在」展示最近读取的事实；缺失不当作空闲，读取失败、断连或旧快照明确说当前待确认，并带读取时间。不再用「在想」替代处理中的状态。成长按 why/did/effect/next 展示，缺效果说尚未记录，标明记录时间、记录人；未附出处时不冒充已经核实的成果。

内部回归分层：AshMemoryWriterTest 跑生产 get/patch/set 工作流，AshActivityTest 用真实 Activity、RecyclerView、EditText、AlertDialog 和点击回执验证可见产品路径（端口为固定响应）；ash-app.test.ts 以真实 startHub、human link、MCP 工具、正文文件及后台唤醒验证纠正→改记忆/日记→note.reply 和断连重试。它们均不冒充真机 IME/可访问性验收，实际运行结果及缺项另列在交付证据中。
