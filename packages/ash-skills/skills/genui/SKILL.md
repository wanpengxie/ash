# 在对话里发一张好卡片

想给主人看什么、要他选什么、填什么，**直接在对话里发一张卡**，不让他去设置页或别的地方，也不让他把密码打在对话里。卡片是对话里的一小块屏幕（内容约 300 dp 宽），用的是 App 自己的字号和配色，外框（底色、圆角、内边距）和底部的 👍/👎 由手机画。好卡片 = 一个主角 + 少量必要的细节 + 至多一个主要动作。

| 工具 | 干什么 |
|---|---|
| `human_show {id, text, a2ui}` | 发一张卡；`id` 以后改它用，`text` 是一句纯文字摘要（通知、锁屏显示它） |
| `human_card_update {id, a2ui?, data?}` | 改原卡，不发新卡 |
| `human_form {title, why, schema, secret?}` | 一张表单卡，填完点「提交」才回来；`secret` 字段是密码框 |
| `capability_call {member: "person:owner", word: "card.preview", body: {id, theme}}` | 看手机把这张卡画成什么样（一张图） |

本目录（容器里 `/opt/ash/ash-skills/skills/genui/`）：`patterns.md` 版式对照表、`examples/` 每种版式一份能直接改的样例（文件内容就是 `human_show` 或 `human_form` 的参数）、`rules.md` 尺寸留白颜色组件的细规矩、`checklist.md` 发前自查、`feedback.md` 怎么记主人的口味、`mechanics.md` 按钮、改卡、表单、保险箱、小页面怎么用、`runtime.md` 卡片背后的后端、按钮直接调词、实时数据和休眠。

## 发不发卡

- 一两句话说得清的（「快递中午到」）只说话。多条或多列的数据、对比、时间线、数字和趋势、要勾选填写确认的、要回头再看的（行程、清单、菜谱）才发卡。
- 一次一张，一张只做一件事。气泡里一句话说结论，卡片放细节，两边不重复。

## 只展示，还是要后端

卡片可以是完整的小应用。只是看、在卡上切换勾选、按钮让你接着做：只发卡。按钮要直接做事（建日历、记一笔）、数据要一直更新（心率、价格）、要存东西：先照技能 `build-app` 写一个应用、`needs` 写清要用的词，再 `human_show {app, temporary_app}` 发卡，按钮用 `{call}`，数据用 `a2ui.sources`。做完事收起卡（`card.close`）。细节和例子（心率实时图、记账卡、确认预约）在 `runtime.md`。

## 每次的做法

1. **看口味**：读 `/root/work/design/TASTE.md`；有 `/root/work/design/gallery/` 就看主人点过赞的同类卡。它们比本技能的默认优先。
2. **选版式**：在 `patterns.md` 挑最接近的一种，打开 `examples/` 里对应的样例照着改，不从空白写起。
3. **先想清楚**：主角是什么（一个结论、一个数字、一个状态）；从上到下的顺序；唯一的主要动作，或者没有动作。
4. **写 a2ui**，守住下面的硬规矩，`human_show` 发出。
5. **读回包**：`problems` 是被丢掉的部分，`hints` 是让卡变丑的写法（accent 太多、不止一个大标题、图标或徽标多于一个、不止一个主按钮、十六进制色、根上加框、文字里有 emoji）。不为空就用 `human_card_update` 改好。
6. **看一眼图**：`card.preview` 拿到手机上的样子，挤、截断、对不齐、平线图就改；没连手机（`offline`）就跳过。
7. **主人点了 👍/👎 或说了好坏**：照 `feedback.md` 记下来，下次照着做。

## 硬规矩

1. **外框手机画**：根 `Column` 不写 `background`、`padding`、`cornerRadius`，不再套 `Card`。
2. **留白用 `gap`**：容器的 `gap` 是子元素之间的距离，不写就是 0。三档：标题和它的说明 2、行与行 8、块与块 14（根 `Column` 写 `gap: 14`）。某一个子元素要不一样时才给它写 `style.margin`。
3. **一个主角**：全卡至多一处 `h1` 或 `h2`，其余 `h3`、`body`、`caption`。
4. **颜色少**：只用主题名；`accent` 至多两处（主按钮算一处）；`green`/`red`/`orange` 只表示好坏和状态（行情涨红跌绿）；重复的元素不用 `accent`。
5. **不加装饰**：文字里不放 emoji；`Icon`（单色线性图标，跟着 `color`）全卡至多一个；`Badge` 至多一个。
6. **字要短**：标题一行（≤ 14 字）；一行一件事；只放主人问的，不写大段「建议」「总结」。
7. **只用查到的数据**：不编数字、不凑条目。
8. **动作少**：至多一个 `primary` 按钮放最右，次要的用 `borderless`；只是看的卡不放按钮。勾选、切换、选择、滑动用 `{path}` 绑定，在手机上当场生效。
9. **要密码一律 `human_form` + `secret`**，字段 ≤ 6 个，能给默认值就给。

## 好的样子

主人问「明天要带伞吗」。查到明天 15:00 起有雨、14–19°、降水概率 80%。气泡说「明天下午有雨，带伞」，再照 `examples/answer.json` 发一张结论卡：根 `Column` 的 `gap` 是 14；第一块是 `h2`「明天下午有雨，带伞」前面一个 `rain` 图标，下面隔 2 一行 caption 写日期和地点；第二块三个数字并排（`h3` 数字上、caption 说明下）；最后一句灰字提示。回包 `problems`、`hints` 都空；`card.preview` 看到三个数字挤在一行没有折行，就不再动。主人点了 👍，你把这张卡存进 `/root/work/design/gallery/answer-2026-10-15.json`，下次问天气照它做。

## 常见错误

- 一张卡塞下所有查到的东西；根上再套一层底色或 `Card`，框里有框。
- 每个子元素各写 `margin`，或干脆没留白，块和块贴在一起；该用容器的 `gap`。
- 每行一个图标、彩色字到处都是；文字里放 emoji。
- 股价、体重这类走势画成贴底的平线：给 series 写 `min`（比最低值略低）。
- `ChoicePicker` 的 `value` 写成字符串；要写数组（单选也是 `["15:00"]`）。
- 主人每点一下都发一张新卡；该 `human_card_update` 改原卡。
- 让主人去设置页填东西、把密码发在对话里，或一个字段问一轮。
- 气泡里把卡片内容再说一遍。

## 怎么核对

- `human_show` / `human_card_update` 的回包 `problems` 和 `hints` 都为空。
- 按 `checklist.md` 过一遍；`card.preview` 的图里没有挤、截断、对不齐和平线。
- 改完一张卡，对话里还是那一张（同一个 `id`），不是多出一张。
- 用了保险箱的命令，输出里密码是 `***`。
