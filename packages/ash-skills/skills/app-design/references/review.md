# 看图验收

先打开实际 PNG，别只读 HTML 或功能报告。原图按360dp观看，再放大查字和边界。一次评本次提交，不因为想象的低频极端情况拦稿。

必须核对：
- 先看应用地图：主空间/对象/动作/手势/返回/规划边界明确；从独立入口走主空间、抽屉、滑动与关闭返回，不把单屏通过当App通过。
- 第一眼能指出屏幕主角、正在发生的事与下一步；首屏有明确的内容焦点，不是「分组标题+圆角组+行+右箭头」的设置页。
- 主行动只有一个，其他动作有层级；没有一排文字链；每个动作在现有能力内。
- 真实中文长度，必要时间/状态不截断，无挤压、重叠、底栏遮盖、横向滚动。
- 48dp触控，正文对比度4.5:1；标记测量值，别只凭看着差不多。
- accent≤2，中性色为主，图标来自同一家族；没有渐变/emoji/装饰卡墙。
- 动态状态有依据：没有分步不画假百分比，没有活动数据不写「正在跑测试/读了几个文件」；连接与执行分开。当前、等待、失败、成功语义可信；示例数据在说明中标记；失败有清晰恢复路径。
- 同类页面同一套行、字、间距；来源与返回清楚；核心原型路径可点击走完。

五维快速复核：用户目的、信息层次、交互明确、执行细节、克制。每维用一句可见证据，不靠总分补偿实质问题。

独立验证者返回：
```
结论：done | needs_work
已打开：具体PNG文件
问题：屏名/位置 → 看见什么 → 用户为何受影响
修改建议：最小可执行改动
边界：未验证的交互或真机行为
```

`done`表示本轮设计稿通过，不表示主人批准、Android已实现或可以发布。`needs_work`只拦可观察的使用与设计问题；喜好差异作为建议。修改后重验受影响图，不无限扩大检查矩阵。

Agent原生另核对：是否分清目标/运行/授权/证据；回来能否定位变化、待处理和下一步；决定附近有无必要依据、代价及可逆性；能否直接纠正/暂停/接手；完成是否有可检查产物与未验证范围。缺阶段就不画阶段，缺分母就不画百分比，缺估计就不写ETA。模型、交互、视觉分开给证据，按钮检查不代替产品判断。
