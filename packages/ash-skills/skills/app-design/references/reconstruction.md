# 用理论打碎具体材料，再构造新规范

此方法用于完整应用建模，先于地图和单屏。先读项目给出的概念文档与原则；理论决定如何重组，优秀产品的真实材料提供可重组的元素。已有可追溯材料可复用，不为流程形式重新调研。

## 第1步：可回溯的材料

逐应用列对象、属性、状态、操作、流程、视觉/动效/文案规范；给每个具体元素稳定ID。另列系统的字阶、颜色角色、间距、形状、动效、组件体系。每行附主来源、可见证据和观察边界。区分：官方规范/源码值；截图原像素测量（误差、倍率未知）；本项目建议。静图不能证明触控、实际流程或毫秒数；早年教程图不冒称当前整套产品。

## 第2步：每个旧元素依次答十问

|透镜|对该具体元素必须得出的答案|
|---|---|
|1 角色重分配|主人、主agent、帮手、外部、时间各做什么；谁负责/执行；旧操作保留、消失、退成决定还是过程展示。|
|2 语义归属|持续实体的目标/主线、任务、记忆、人格、自我迭代哪一部分；主人侧理解与agent自身侧分开；运行与实体不等号。|
|3 接口化|哪个成员/词承担读写、什么事件刷新；人和agent同接口。缺词明确列缺口；密钥明文/回答审批等项目明确特权不扩散成旁路。|
|4 关卡与授权|实际风险/范围、一次许可或规则、谁能收回；决定只记录人的选择，后续执行仍经原agent/词/关卡，需要时以主人身份进入原前台上下文。直接写事实与批准执行分开。|
|5 各面与账本|控制、数据、协作分别是什么；哪些起止/撤回/一次动作记账，哪些原文件/高频流只用引用。不能复制感知数据进控制账本。|
|6 身体与多设备|实际body资源、哪只hand、按需/定时/实时sensor、哪个organ；同机可兼角色，跨设备身份/context如何保持。不要把设备、执行者、实体混为一体。|
|7 上下文来源|主人陈述、原对话、观察、外部数据或推断；依据/时效/适用范围是什么；推断何时需要确认，缺来源如何明说。|
|8 注意力与时间|真正需要人、后台余光、回来汇总哪一档；前后台线及实时/分钟/天/长期；名下归属不自动成为当前打断。|
|9 呈现分工|开放意图用语言，稳定对象/关系用GUI，有限决定用卡片，当前比较用生成局部；卡片仍属于原应用，不把全应用退回消息列表。|
|10 简洁与证据|人需要理解的少数概念是什么；复杂度按需展开；低频粗兜底而非完备机制；产物、改变、实际验证和未验如何看。|

一行十栏过宽时可拆成两表，沿用同一旧ID；共同结论可引用，但每个元素仍须交代自身影响，不能只抄“同API、经关卡”。没有变化也写保留理由。对未取证信息写未知，不以漂亮布局倒推一个后端字段。

## 产物与检查

- 新领域模型列保留/新增/退化/消失维度，人的动作与agent动作、真实词与事件、当前能力和缺口；关系源自材料，不照搬旧的人工执行流。
- 新领域设计规范说明每个维度怎样呈现：例如个人勾选与agent交付不同、连接/授权/运行不同、回答/核验/目标完成不同。参数留到第3步形成统一规范，不能拿阶段/百分比/ETA装信息丰富。
- 已有稿件单列差异：旧元素与证据→新归属→具体规范/组件/页面需改什么→文案、布局还是接口缺口。允许推翻旧稿；没有实质变化也给证据。尊重本轮冻结/施工边界，不在多条线暗自改稿。
- 第3步才能在上述结果上构造领域/视觉/动效/文案/组件规范、正反例，再做地图与屏稿。研究发现接口缺口不等于获准建设新服务、权限或运行框架。
