# 具体规格的最小核心

项目已有SPEC就读它并逐条验；没有时先写具名规则+检查+正反图，再画屏。不得只有原则口号。

## 领域与选择

- 责任人、执行者、依赖、一次运行、产物与现实结果分开；同id跨空间/回调不串对象。完成/取消不覆盖原说明。
- 你：中性「你」头像；Ash：原Ash头像；帮手：原名字/首字；外部：globe+「等谁」；时间：clock+明确用途/日期。头像只代表执行者，不能贴到设备上。
- 决策六型：二选一先比差异/代价；多选一具名候选和同属性比较；批准/打回绑定对象与本次范围；时间用系统选择且分提醒/截止；补信息只问缺的一项；验收先产物/检查/未验。依据→后果→有限行动，不藏关键代价。
- 有效报价的低风险比较可给明确的推荐草稿和实色「选择X」，必须人主动确认，不能当已决定/已下单。改条件清空草稿和旧推荐；授权/命令/人格修改不能默认许可。
- 结果展示真实文件/原记录/检查范围；缺diff或测试数就用实际产物，不能造摘要成绩。取不到设备association就不挂工作；权限只呈现实际支持的范围。

必要文字对比>=4.5:1，必要图形>=3:1。身份色不代替成功/警告/失败；颜色配文字。没有电量/阶段/比例/ETA就省，不为丰富加数据。没有实际照片用具名文字比较，插画不能冒充商品证据。多个决定给真实可见数量入口，不铺巨卡；无已见游标不称「离开后N变化」。

## 动效与文案

Ash基准curve(.32,.72,0,1)：反馈160ms、新需你240ms最多8dp一次、完成确认300ms、抽屉360ms。后台不循环动，只有真实当前请求等待可用局部等待指示；系统移除动画直接落位，保留文字/证据，不重播入场。

状态说事实：已保存、已提交、已接收、执行中、产物已生成、目标已确认分别写。未知给最后确认，不能叫空闲。标题一般<=14汉字、问题<=20、按钮2–6字；关键对象不截断，必要时换行。依据/后果通常各2行，关键代价不能藏。按钮用具体动词，不用「好的/搞定」。
