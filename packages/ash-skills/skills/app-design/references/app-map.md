# 先做应用地图

完整App不能用一张好看的首页代替。先定用户会长期进入的几个主空间，再画单屏；主空间不是把接口名排成标签。

一张地图写清：

- **身份**：应用图标、名称、主题角色、独立启动首页；顶层没有返回Ash的箭头。跨应用深链落到同一App和同一对象。
- **主空间**：通常2–4个稳定目的地，各自用途与默认内容。底部标签或顶部分段只选合适的一种；对象详情用抽屉或子页，关闭后回到原空间/位置。
- **对象与动作**：对象id、从哪里新建、怎么找到、点开看什么、能改什么、结果回哪里。同一对象在多个空间仍是一份状态。
- **手势**：点击、左右滑、长按、拖动、下拉分别干什么，哪些只是露出操作、哪些需要确认；给按钮等价入口，不能只能猜隐藏手势。拖动只能映射到真实能力；没有排序存储不要假造长期自由排序。
- **状态与范围**：处理中/失败/空状态怎么继续；未完成表单和阅读位置切标签不丢。未实现的主线/标签等放规划区域，不画成已可用。
- **路线**：入口→主空间→列表对象→详情/抽屉→操作→反馈→关闭返回；外部通知/跨App打开也落同对象。

先输出一张可看懂的地图（HTML/PNG或简洁图），再按它交付主空间、抽屉、至少一张滑动状态和关键操作路径。独立验证者既看图也实际从入口走路径，确认不是几张孤立海报。

导航栏不以「隐藏高级功能」为由反复消失或变标签；模态抽屉盖住底栏时，关闭后仍是同一空间。图标用现有线性家族组成应用自己的入口标识；主题角色在同一令牌系统内区分。原型动画只解释切换、露出操作和结果，减少动画时直接完成。

应用地图在领域建模和视觉编码之后。先写人的动词与agent的动词，再让空间从人的目的长出来，不从接口或传统待办标签倒推。地图要表达离开再回来时变化的入口、判断所需证据、暂停/直接纠正/接手和结果验收；这些概念不要求新增后台状态机。
