## 三、全局问题（各页反复出现）

- **§2.1 刷新整块重建**：主页各分页都靠 `HomeKit.redraw`（`removeAllViews`）整块重画，体检、应用列表、应用页也一样。聊天和 Codex 已经改成 `KeyedRowsAdapter`，其余页面下一轮照这个迁移。
- **§3.2 请求机制**：`HomePage.call` 没有超时、代次，也不限制同源只留一个在途；`HumanPort` 现在已经有时限，主页这条路径还没有。
- **§7.2 裸建线程**：HomeMain、HomeHands、HomeFiles、AppsPane、Console、Onboarding、ChatFiles、LeaseState 都是每个请求新建一个 `Thread{}`，应改走 `UiIo` 或 `HumanCall`。
- **§11.2 返回**：Console、Onboarding、AppActivity 仍然重写 `onBackPressed`；`BackRouter` 已经可以复用。
- **§5.5 / §5.6**：可点的 LinearLayout 单元格缺角色；原生文案都写在 Kotlin 里，没有进字符串资源（`strings.xml` 只有 7 条）。
- **§3.4**：页面状态挂在 Activity 或页面对象上，没有 ViewModel 或等价的 retained 状态。聊天和 Codex 现在已经有 saved state 加持久草稿。

## 七、简化第二轮（2026-10-15，主人：「不要过度复杂化」）

用最简单的常规做法替换第二轮为应对审核反例加的机制，第一轮的骨架保留（先入队后清稿、失败不清历史、每会话草稿、RecyclerView、Insets 协调、状态浮层、返回、48dp）。

- **Codex 对账**：删掉电脑端按「同文本 + 顺序」认领消息、items 上的 client_id 和整轮位置。现在 `x.codex.send` 在开新 turn 时返回该 turn 的 id（真 App 填在哪个字段**未验证**），手机记下 client_id → turn（和聊天的 sentAs 一样），读到这个 turn 时，turn 里的第一条用户消息接替待发那一行。拿不到 id 时，发送成功就去掉待发行并立刻刷新一次。不再有「不确定」状态：失败或没回音都显示「没发出去」，重发用同一个 id。
- **新建会话**：结果未知后再点重试，可能会开出第二个会话。这一点不加机制：没回音的操作本来就不会自动重发，由主人决定要不要再试。
- **阅读位置**：只存第一个可见行的 key 和偏移；重建后这一行在已加载的行里就回到原处，不在就显示最新，不再额外去拉它附近的消息。
- **跟随最新**：提交前看一次是否在底部，在底部就在提交完成后跟到最新；主人发送时直接到底。
- **代次**：Codex 读取只看一个代次计数，每次切换页面都会加一。往上翻的分页只有读到更早的消息时，才更新「还有更早的」。发送后，附件按「前 n 个就是发出去的」直接去掉。
