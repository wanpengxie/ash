# ASH-602/307 isolated cross-device probe

Scope: a Mac Chrome isolated profile and an Android API 36 emulator WebView ran the same generated browser shell against one temporary localhost echo owner. The Mac-to-Linux connection used one dedicated localhost SSH forward; the emulator used an `adb reverse` of that same port. Both clients used a synthetic owner token generated for this temporary state directory. No existing browser profile, application package, calendar, or owner database was used. This is two devices but not a physical-phone result.

The reproducible fixtures are `tools/spikes/v2-cross-device-server.mjs`, `tools/spikes/v2-cross-device-android.mjs`, `tools/spikes/v2-cross-device-mac-cdp.mjs`, and `packages/core/ui/test/android-webview/`. First establish the dedicated localhost forward and `adb reverse tcp:14762 tcp:14762`; build/install only the fixture package; start the echo owner on Linux with `ASH_PROBE_MAIN` pointing at the exact core checkout; copy only the generated mode-0600 synthetic URL file and Mac CDP script to the Mac; run the CDP script's `start`, `verify`, then `stop` commands against a fresh isolated Chrome profile. The Android launcher takes the generated URL file. The scripts do not print the token. When repeating, use a fresh state directory and do not reuse the prior token or ledger.

F-U22 observations came from the earlier isolated echo process with the merged 602 shell and a 307 candidate. That process did not have a working post member, so its 404 presence attempts are excluded from F-U21. The F-U21 process was restarted with a fresh state directory and 307 source at `557252f`.

The Mac CDP checked registration plus both Android messages and the Phone browser label in its DOM. The Android fixture was foregrounded before its accessibility dump; an exact-text extraction of that dump returned `text="来自 Computer browser"` and two `text="mac_probe_one"` nodes (owner and agent echo bubbles). After the second Android send it returned two `android_probe_two` nodes: the right-side owner bubble at x637–1042 and the left-side agent echo at x42–903. The ledger has only one owner request for `android_probe_two`, at seq 65, so these are not duplicate owner submissions. These checks establish live two-way presentation and source labelling for this Mac-plus-emulator pair; a physical phone remains untested.

For F-U21, the initial echo process was started before the post member was present and returned 404; it is not counted as a successful heartbeat. A fresh isolated process imported the final 307 `startOwner` with a real `PostPresenceMember`. The Android WebView produced `visible` ledger entries at 1790821667800, 1790821697745, and 1790821727739 ms (roughly 30 seconds apart), all from the same registered screen. After pressing Home, the count stayed at three through a 36-second background window. Reordering the same activity to the foreground added one immediate `visible` at 1790821811191 ms, again from the same screen. In a second pass, the count was seven before Home and stayed seven across roughly 70 seconds in the background; on returning the same activity to the foreground, two `visible` events were recorded 11 ms apart, from the same screen. The shell's visibility event and scheduled timer can both request a harmless presence refresh; this probe does not assert exactly one refresh. It verifies browser emission/stop/resume and real post intake, not the server's 60-second registry expiry, which was not read from this external process.

The original temporary ledgers and Android accessibility dump were deleted during exact fixture cleanup; this report records the author-observed command results, not retained raw artefacts or hashes. Independent review should rerun the scripts and save its own raw ledger/CDP/UI outputs before cleanup. The test Mac profiles, emulator reverse, fixture package, synthetic files, temporary state directories, and the dedicated SSH forward were removed; the Mac-side check found neither test port listening afterward. These results do not establish a production gateway, a physical phone, or later page flows.
