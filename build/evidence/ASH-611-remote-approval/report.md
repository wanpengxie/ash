# ASH-611 remote approval answer increment

This increment enables the Approval tab to answer only still-pending, ledger-derived `service:gate` asks using their offered `once` / `always` / `deny` choices. The current registered screen token, screen ID, authentication scope, registration generation and open-page epoch fence both the send and its result. An HTTP acceptance alone never displays success: the matching response ID, sequence, route, `reply_to`, choice and screen origin must appear in the authoritative ledger projection. An unknown acknowledgement retains the same choice and `client_id` for an explicit retry; double-click does not send twice. Account switching, disconnection and page closure discard the in-memory intent.

The remote Approval tab does not show or call rule mutation, access administration or local pause/resume. Complete approval history and rule-list management remain explicitly unavailable here. This does not complete the full settings card.
