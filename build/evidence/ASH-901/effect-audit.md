# AR6 effect-to-ledger detector foundation

`packages/core/test/arch/effect-audit.ts` is a pure checker for four separately observed effect classes: device calls, notifications, intrinsic file writes, and gate releases. It requires nonempty ledger and observed-effect inputs, all four effect classes by default, unique effect-to-message attribution, exact target/word/body and (where observed) result equality, and a unique later response with the request's reverse sender/recipient and same word. A successful intrinsic write requires `self.changed` between request and response, with matching path, caller, and response version. A gate release must precede its associated `request_id`; this checks only explicitly observed protected calls, not every device call (including owner-direct calls). A notification must be recorded as notification delivery, not merely queued or held.

Eight executable fixture tests include a valid four-effect trace with gate release before protected device request, plus deliberate omissions, wrong arguments/target/result, forged response identity and word, duplicate attribution/response, unrelated or late file-change events, absent version, false notification outcome, forged/late/unassociated gate events, and ledger reordering. These fixtures validate the detector only. The `self.changed` correlation is limited to available path/caller/version/time fields; it is not a cryptographic causal proof or a substitute for runtime atomicity. They do not claim AR6 production conformity: the real scenario adapter and independent side-effect capture are blocked on the v2 world, post, self, gate, and host implementations. The adapter must record observations outside the ledger and then compare with persisted ledger rows; copying ledger rows into the observed side would be vacuous.

Reproduce: `node --import tsx --test packages/core/test/arch/effect-audit.test.ts`. A full `npm test` run includes this file.
