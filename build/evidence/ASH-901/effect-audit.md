# AR6 effect-to-ledger detector foundation

`packages/core/test/arch/effect-audit.ts` is a pure checker for four separately observed effect classes: device calls, notifications, intrinsic file writes, and gate releases. It requires nonempty ledger and independently observed effects supplied in chronological order, all four effect classes by default, unique effect-to-message attribution, exact target/word/body and (where observed) result equality, and a unique later response with the request's reverse sender/recipient and same word. An intrinsic write requires `self.changed` between request and response with matching path and caller; if the response supplies a version, the event version must match. The append, apply-plan, and rollback contracts do not return a version, so their path/caller/time match remains explicitly **unverified**, not a false pass or a claim that a valid write failed. A gate release must identify an existing request; the independently observed gate release must precede that request's actual device-call effect, though the request may already be in the ledger. This checks only explicitly observed protected calls, not every device call (including owner-direct calls). A notification must be recorded as notification delivery, not merely queued or held.

Nine executable fixture tests include a valid four-effect trace with request→gate→response ledger order and gate→device external-effect order, plus deliberate omissions, wrong arguments/target/result, forged response identity and word, duplicate attribution/response, unrelated or late file-change events, missing version marked unverified, false notification outcome, forged/late/unassociated gate events, direct device call without gate, and ledger reordering. These fixtures validate the detector only. The `self.changed` correlation is limited to available path/caller/version/time fields; it is not a cryptographic causal proof or a substitute for runtime atomicity. They do not claim AR6 production conformity: the real scenario adapter and independent side-effect capture are blocked on the v2 world, post, self, gate, and host implementations. The adapter must record observations outside the ledger and then compare with persisted ledger rows; copying ledger rows into the observed side would be vacuous.
