# 803 / 804 内容交接

三份技能文件的头部字段由脚本调用安全 YAML 解析器检查。`mock.json` 记录十个输入实际送进脚本假模型、解析输出再判定的轨迹；另把一个正确分类故意改错，判定器确实拒绝。它证明夹具和判定器能运转，**不证明语义模型的质量**。

`live.json` 记录官方模型 `deepseek-flash` 的可见输出和三份技能文件的 SHA-256。最终一轮十类起名判断 10/10 与预期一致，另有三条自我认知和三条遗忘语言样本；全部正常结束，自动标记零。早期迭代里，模型曾在被问助手名字而用户只回答“叫我 X”时再次追问；已把该分支和反例写入技能。单轮抽检不能保证此分支在所有运行中稳定，建议非作者专门重测。

人工核对最终可见回复：无名字输入没有被写作名字；拒绝起名后进入起步选项；没有成功保存时不宣称已经长期记住。已读资料中的一条偏好没有被扩展成未读资料的断言；读取失败的样本先说明无法核实。遗忘样本在同意前只列计划、拒绝后不声称写入，也不虚构此前调查范围；成功写入但复查缺失时不宣称彻底忘记。

三个起步选项分别可通往整理用户提供的事项、已接入的定时能力、内在资料写入。七天提示分别邀请任务拆解、定时提醒、保存偏好、压缩文字、安排拥挤日程、调整回答风格、指出一处待改进；每条都可以从用户的下一句话开始，不承诺动作已经发生。触发时间和停止投递属于外部流程，不由技能宣称已验证。

`tool-loop.json` 另有一轮真实 DSH 模型服务 + 真实模型工具调用，但所有工具只操作内存夹具。轨迹显示：选项展示一次；整理事项走日历查询；提醒走定时调用；偏好先读再写；遗忘在同意前零写、拒绝后仍零写；明确同意后两次写入及两次复读，最后只声称当前两处记录已移除。脚本对这些关系逐项断言。曾有一轮未限定可搜索位置的工具测试触发过多读取并截断，最终脚本把隔离夹具范围写明并限定相关动作；截断那轮没有被计作通过。

上述 DSH 回路不是生产 agent 会话，也不是真正点击选项卡或调用生产内在、时钟服务；不能据此签署完整 F-C03/F-C05/F-C06 集成结果。本轮没有删除或改动真实用户资料。`originality.json` 是三份技能和本报告的整文件比对结果：465 个私有参考文件，按规范化段落检查，无超过 12 字的重合；报告不包含参考原文或路径。

复现结构检查：`node tools/spikes/skills-review.mjs --mock`。真模型抽检：为当前进程安全提供 `ASH_CONTENT_API_KEY` 后运行 `node tools/spikes/skills-review.mjs --live`。隔离工具回路：安全提供 `DEEPSEEK_API_KEY` 与已安装的 `ASH_TEST_DSH_ROOT` 后，通过 TypeScript 运行器执行 `tools/spikes/skills-tool-loop.ts`。没有密钥时不会调用模型。脚本只向官方端点发送请求，保存可见答复，不保存凭据或隐藏推理。
